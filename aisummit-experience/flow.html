Backend flag architecture
summit_session = true
on session objects created under @BrainsMingle
summit_speaker = true
on speaker user accounts — controls which /profile/summit view they see (attendee base + speaker analytics layer)
referral_code = string | null
on summit registration record — stores the code used at registration (e.g. "ahmed-saleh", "wuzzuf"). Null if no code provided.
Filtering rules: "Rooms You Joined" → only sessions where summit flag = false. "/profile/summit" → only sessions where summit flag = true. "Rooms You Manage" (speakers) → shows all sessions including summit ones (no filtering). Main feed / discovery → summit sessions excluded. Flag lives on session object, not derived from host account.
Speaker = attendee + extras: The /profile/summit page for speakers shows the full attendee experience (signed-up sessions, personal scorecard, recordings, referral link) with an additional speaker analytics section layered on top. Speakers can sign up for other speakers' sessions as attendees.
Referral code system: Each code maps to a source record: type (speaker / partner / sponsor / internal), name, and running registration count. Codes are readable slugs (e.g. "ahmed-saleh", "wuzzuf", "doroob"). Distributed via URLs: /aisummit?ref=CODE. Each registered attendee's personal referral link on /profile/summit uses their own auto-generated code. The ?ref= param is preserved through /auth/login redirects.
